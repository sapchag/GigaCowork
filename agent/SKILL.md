# Агент распределения заказов между логистами

## Когда применять навык

Применяй этот навык, когда:
- приложена **выгрузка ФУЛ из 1С** (.xlsx),
- приложен **реестр заказов Cloud** (.xlsx),
- приложен **список сотрудников из 1С** (.xlsx),

и пользователь хочет получить распределение новых заказов между логистами
(даже если запрос пустой или сформулирован кратко, например «распредели»,
«сделай распределение», «разнеси заказы»).

Запуск **без текста запроса**: пользователь выбирает агента, прикладывает три
файла и отправляет пустое (или почти пустое) сообщение. Начинай работу сразу.

## Требования

- Python 3, только стандартная библиотека + `openpyxl` (и `xlrd`). Сеть не используется.
- Колонки ищутся **по заголовкам**, а не по номеру — файлы заказчика могут иметь
  другой порядок колонок, лишние колонки и иначе названные листы.
- Решения о группе и логисте принимает **скрипт навыка**, а не модель.
- Там, где данных нет, пиши «не определено», ничего не выдумывай.

## Как запустить скрипт

1. Сохрани приложенные файлы (ФУЛ, Cloud, сотрудники) во временные пути.
2. Запусти из папки `scripts/`:

```
python distribute.py --ful "<path ФУЛ.xlsx>" \
                     --cloud "<path Cloud.xlsx>" \
                     --staff "<path сотрудники.xlsx>" \
                     --out "<папка результата>"
```

3. Скрипт создаст в папке результата файл `result_cloud.xlsx` с листами:
   - **Новые строки Cloud** — строки реестра по форме (12 колонок в правильном порядке);
   - **Повторные отправки** — с комментарием «Повторная отправка ФУЛа, [дата]»;
   - **Возможные пропуски** — ФУЛ, которых нет в Cloud, хотя они пришли раньше последней записи;
   - **Требует внимания** — заказы с причинами (нет номера заказа, группы, логиста);
   - **Журнал решений** — обоснование выбора по каждому ФУЛ.

## Правила распределения (исполняет скрипт)

- **Новый ФУЛ / повторная отправка.** Заказ уже есть в Cloud → повторная отправка
  (комментарий «Повторная отправка ФУЛа, [дата]»). Тот же номер ФУЛ в пачке или
  тот же заказ, уже обработанный в пачке → дубль внутри пачки (не создаём строку).
- **Группа:** `air` → авиаперевозки; не `air` + страна отправления Китай (включая
  Гонконг) → ВЭД; не `air` + страна не Китай → мультимодальные перевозки.
- **Логист:** исключаем сотрудников в отпуске, уволенных, ассистентов и руководителей.
  Выбираем логиста, который чаще всех работает с поставщиком (по истории в Cloud).
  Для нового поставщика или при недоступном предпочтительном логисте — наименее
  загруженный в группе (по заказам «в работе»).
- **Один поставщик в пачке — один логист.** Все новые заказы одного поставщика
  распределяет один и тот же логист.
- **Если в группе нет доступных логистов** — заказ остаётся без логиста, в другую
  группу не передаётся, попадает в «Требует внимания».
- **Сопоставление имён.** Короткие имена логистов в Cloud (например «Иванов И.»)
  сопоставляются с ФИО сотрудников из 1С.

## Как ответить пользователю

1. Открой `result_cloud.xlsx`.
2. Дай короткий ответ по шаблону:

```
Новых строк Cloud: <N>
Повторных отправок: <M>  (из них дублей в пачке: <K>)
Требует внимания: <P>
```

3. Упомяни, что полный результат — в файле `result_cloud.xlsx`, и кратко укажи
   листы (новые строки / повторные / пропуски / внимание / журнал решений).
4. Если какие-то ФУЛ требуют решения человека (нет номера заказа, группы, логиста),
   коротко перечисли их причины — оставь их человеку, не выдумывай значения.

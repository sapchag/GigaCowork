# Инструкция по установке и запуску агента

## Состав архива агента

```
agent/
  SKILL.md                     # файл навыка (YAML-блок + инструкция модели)
  system_prompt.txt            # системный промпт агента GigaCowork
  scripts/
    distribute.py              # скрипт распределения (правила решает он)
    gigacowork_lib.py          # вспомогательные функции
  references/
    distribution_rules.md      # справочник групп, должностей, формы реестра
```

## Требования

- Python 3.8+ (проверено на 3.14).
- Пакеты: `openpyxl` (для чтения/записи .xlsx). Для .xls файлов дополнительно `xlrd`.
  ```
  pip install openpyxl
  pip install xlrd        # только если нужно читать .xls
  ```

## Установка в GigaCowork

1. Создайте агента в пространстве GigaCowork.
2. В поле системного промпта вставьте содержимое файла `agent/system_prompt.txt`.
3. Подключите навык: загрузите папку `agent/` как навык (в ней должен находиться
   `SKILL.md`, папки `scripts/` и `references/`).
4. Навык применится автоматически, когда пользователь приложит три файла Excel
   (ФУЛ из 1С, реестр Cloud, сотрудники из 1С).

## Запуск в агентной среде (GigaCowork)

1. Выберите агента.
2. Приложите три файла `.xlsx`:
   - выгрузка ФУЛ из 1С,
   - реестр заказов Cloud,
   - список сотрудников из 1С.
3. Отправьте сообщение **без текста** (пустое) — агент начнёт работу сам.
4. Навык запускает скрипт `distribute.py`, который:
   - находит нужные колонки по заголовкам (порядок и наличие лишних колонок не важны);
   - определяет новые ФУЛ, повторные отправки, дубли в пачке;
   - выбирает группу и логиста по правилам;
   - формирует `result_cloud.xlsx` с 5 листами.
5. В ответ агент печатает краткую сводку и прикрепляет `result_cloud.xlsx`.

## Запуск скрипта напрямую (без агентной среды)

```
python distribute.py \
    --ful  <путь к ФУЛ .xlsx> \
    --cloud <путь к реестру Cloud .xlsx> \
    --staff <путь к списку сотрудников .xlsx> \
    --out  <папка результата>
```

Скрипт создаст в папке результата файл `result_cloud.xlsx` с листами:

- **Новые строки Cloud** — строки реестра по форме (12 колонок в правильном порядке);
- **Повторные отправки** — с комментарием «Повторная отправка ФУЛа, [дата]»;
- **Возможные пропуски** — ФУЛ, которых нет в Cloud, хотя они пришли раньше последней записи;
- **Требует внимания** — заказы с причиной (нет номера / группы / логиста);
- **Журнал решений** — обоснование распределения по каждому ФУЛ.

## Воспроизведение тестов

Структура папок проекта (для повторного прогона):

```
data/
  generate_data.py             # генератор синтетических данных и эталона
  datasets/                    # сгенерированные наборы (ful_1c/cloud/staff_1c/etalon)
tests/
  run_tests.py                 # прогоны всех наборов по 3 раза + метрики
  compare_with_etalon.py       # сверка результата с эталоном
  metrics/                     # test_metrics.json и result_cloud.xlsx по прогонам
```

Чтобы пересобрать данные и метрики:

```
python data/generate_data.py --out data/datasets/set1   --mode full --seed 42
python data/generate_data.py --out data/datasets/set_trap --mode trap --seed 42
python data/generate_data.py --out data/datasets/set_chk --mode chk  --seed 42

python tests/run_tests.py \
    --datasets data/datasets/set1,data/datasets/set_trap,data/datasets/set_chk \
    --runs 3 \
    --distribute agent/scripts/distribute.py \
    --compare tests/compare_with_etalon.py \
    --out tests/metrics
```

Результат — `tests/metrics/test_metrics.json` со сводными метриками.
